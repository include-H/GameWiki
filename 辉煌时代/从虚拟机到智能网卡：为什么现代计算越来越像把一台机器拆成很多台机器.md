# 从虚拟机到智能网卡：现代计算把一台机器拆成很多台的技术路线

## 一、导言：机器是可以拆开的对象

在用户眼里，「一台机器」是一整块不可分的东西：有中央处理器（Central Processing Unit，CPU）、有内存、有硬盘、有网口，插上电就能开机。在系统工程师眼里，这块整体由若干可以分别处理的资源拼成，每一类资源都能被切开、分层、再把切开的碎片重新组合成「许多台机器」。整部现代计算基础设施史，很大一部分就是这条切分线不断向前延伸的历史。

切分的顺序大致如下。先是时间：一颗 CPU 的运算能力被切成许多时间片，在时间维度上变成许多颗逻辑 CPU。再是地址：一整块物理内存被切成许多地址空间，每个空间都以为自己独占全部内存。接着是整机：一台物理服务器的处理器、内存与设备被虚拟化成许多台虚拟机，每台虚拟机可以独立安装操作系统、独立重启。然后是设备与存储：一块网卡被切成许多虚拟网口，一块磁盘被切成许多层可以回滚的状态。最后是基础设施本身：网络、存储、安全、管理这些职责被整体搬离 CPU，落到一块自带处理器与内存的网卡上。

虚拟机是这条路上最早、也最显眼的一站，却不是终点。把虚拟机当成这段历史的全部，会漏掉它前面半个世纪的地址空间与时间片，也会漏掉它后面二十年的设备卸载与 DPU。本文按时间与机制两条线交叉展开，逐段说明每一步切开了什么、用什么机制切开、又把什么重新缝合回一个可用的整体。

## 二、时间片：一颗 CPU 如何服务许多人

最早的电子计算机一次只跑一个程序。操作员把一叠打孔卡送到机器跟前，机器从头到尾处理完，再换下一叠。这种批处理（batch processing）方式下，机器的大部分时间花在等待纸带与卡片输入上，真正做运算的时间占比很低，而当时的机器按小时计费、按整机采买，等待就是直接烧钱。

20 世纪 50 年代末到 60 年代初，两条线同时把 CPU 的时间切了开来。一条是中断机制：外设在完成一次输入输出后主动打断处理器，处理器保存现场、处理事件、再返回原处，程序不必再轮询等待。另一条是调度：操作系统按固定长度的时间片（time slice）在多个就绪任务之间轮转，每个任务只被允许运行一段很短的墙钟时间，随后被时钟中断换下。有了这两条，一颗物理 CPU 在任一时刻仍然只执行一条指令流，在若干毫秒或若干秒的尺度上却已经同时「属于」许多个任务。

把这一想法做成完整系统的，是麻省理工学院（Massachusetts Institute of Technology，MIT）的相容分时系统（Compatible Time-Sharing System，CTSS）。CTSS 于 1961 年在一台 IBM 709 上对外演示，由费尔南多·科巴托（Fernando Corbató）主持，投入实际使用后，同一台机器可以同时接受多台终端上多位用户的交互命令。它第一次让「用户」与「机器」之间不再是独占关系，也就第一次把编程从「排一次机房档期」变成「坐在终端前边想边试」。MIT 随后联合贝尔实验室（Bell Labs）与通用电气（General Electric）推进 Multics 项目，试图把分时、分段与多层次存储做成一套通用架构；IBM 则推出 TSS/360，面向自家 System/360 大型机提供交互分时。分时系统的商业动机很直接：大型机太贵，必须让尽可能多的人共用同一台，才能把成本摊薄到可承受。

分时给出的是这台机器被拆开的第一个维度：时间。资源总量没变，同一颗 CPU 在时钟的刻度上被分给了许多人。需要注意，这里的出发点是「多人共用一台昂贵的机器」，与后来云服务按需租售算力的商业模型并不是同一回事；后者的诸多概念要到几十年后才成立。

## 三、地址空间：一整块内存如何变成许多块

时间片之上的下一刀，落在内存上。早期程序直接操作物理地址，一个程序写坏的内存，另一个程序就会读错；程序能看到的全部内存，就是机箱里真实插着的那几条存储。要把内存切成许多份、每份都以为自己独占整块，需要地址翻译：程序发出的地址先经过一层映射，才落到物理存储单元上。

这一层映射最早在曼彻斯特大学的 Atlas 计算机上建成实用系统。Atlas 于 1962 年投入使用，配备一台分页鼓（paging drum），由汤姆·基尔伯恩（Tom Kilburn）团队设计，实现了按需分页（demand paging）：程序假想自己拥有一块连续的、比实际物理内存大得多的地址空间，真实页面按需从鼓上换入换出。这被普遍视为第一套实用虚拟内存（virtual memory）系统，「虚拟内存」这一叫法也出自这一时期的讨论。IBM 在 System/360 的 67 型（System/360 Model 67）上引入动态地址翻译（Dynamic Address Translation，DAT），把虚拟内存带进主流商用大型机产品线：每个任务拥有各自独立的地址空间，页表决定虚拟地址到物理地址的映射，越界访问会触发缺页或保护异常。

地址翻译完成后，操作系统手里的内存从「一块」变成了「许多块地址空间」。每个进程拿到的是一张私有的、看似连续的地址空间，互不可见，也互不干扰。隔离由此从硬件层面成立：一段代码即使怀有恶意，也只能在它自己的映射里乱走。这一层后来成了整机虚拟化的地基，也成了内存虚拟化反复重做的主题——从早期为每台虚拟机维护影子页表（shadow page table），到后来处理器直接支持的嵌套页表，都是同一件事在不同硬件代际上的重演。

## 四、整机虚拟化：CP-67 与 Popek–Goldberg 判据

广播时与地址空间之后，最自然的问题是：能不能让一台机器同时跑好几个完整的操作系统，每个都以为自己独占整机。答案是虚拟机监控器（hypervisor），也叫虚拟机管理程序（Virtual Machine Monitor，VMM）。

这项技术在 20 世纪 60 年代就做成了。IBM 在剑桥科学中心（Cambridge Scientific Center，位于马萨诸塞州剑桥）为修改过的 System/360 设计了一套控制程序（Control Program，CP）；原型 CP-40 于 1967 年在一台改装的 40 型上运行，随后在支持 DAT 的 67 型上发展为 CP-67，与对话式监控系统（Cambridge Monitor System，CMS）合称 CP/CMS。CP 把物理机切成许多台虚拟机，每台虚拟机可以运行一份独立的操作系统，多个用户可以各据一台互不打扰地做开发与测试。IBM 后来把这条路线产品化为 VM/370，于 1972 年随 System/370 推出。CP-67 的动机仍然摆在明面上：大型机太贵，一次只能服务一个操作系统的做法浪费严重，多用户与多开发和测试环境需要共享同一台物理设备。

虚拟机监控器要成立，靠的是特权指令的截获。可以把指令分成两类：普通指令与特权指令。普通指令允许被用户程序直接执行；特权指令一旦由普通程序执行，就会触发陷阱（trap），把控制权交给监控器。监控器在陷阱中检查这条指令是否该被子机执行，决定是模拟、拒绝还是透传。 Gerald Popek 与 Robert Goldberg 在 1974 年发表于《Communications of the ACM》的论文中，把「可虚拟化」整理成了三条要求与一组充分条件：虚拟机在效率上应能几乎以原生速度执行大多数指令；监控器必须对全部系统资源保持控制；虚拟机行为应与真实机器等价。他们给出的条件是：全部敏感指令都必须能被陷阱截获。这篇论文把一种工程技巧提炼成了架构判据，此后几十年人们判断一种处理器是否容易虚拟化，靠的就是这份判据。

麻烦在于，早期 x86 架构并不满足这套条件。它有若干敏感指令在用户态可以安然执行而不触发陷阱，等于漏出了控制权。要在这样的处理器上跑虚拟机，只能另想办法——这条「另想办法」的路，直接催生了 1990 年代末的商业虚拟化。

## 五、Type 1 与 Type 2：Workstation、ESX 与 ESXi

在讨论具体产品之前，需要先分清两类结构。Type 1（裸机型、native）指监控器直接运行在物理硬件上，硬件之上第一层就是它，客户操作系统运行在它之上，代表有 VMware ESXi、Xen、微软 Hyper-V；Type 2（宿主型、hosted）指监控器作为一个普通应用程序跑在一套现成的宿主操作系统之上，再由它托起客户操作系统，代表有 VMware Workstation、Oracle VirtualBox、Parallels Desktop。两类结构在性能、可控性与部署位置上各有取舍：Type 1 控制更彻底、开销更低，但需要适配底层硬件；Type 2 装机即用、便于开发调试，代价是隔了一层宿主系统。

1998 年，黛安·格林（Diane Greene）、门德尔·罗森布卢姆（Mendel Rosenblum）、斯科特·德文（Scott Devine）、爱德华·王（Edward Wang）与爱德华·布尼翁（Edouard Bugnion）在加州创办 VMware。他们的核心手段是二进制翻译（binary translation）：既然 x86 的敏感指令不会全部触发陷阱，就在虚拟机执行指令流之前动态扫描并改写，把有问题的指令替换成会跳进监控器的序列。这套做法让 x86 上第一次出现了可用的整机虚拟化，绕开了架构缺陷。1999 年，VMware Workstation 1.0 发布，属于 Type 2，把整台「虚拟电脑」做成桌面上可以开窗口的程序，开发者在一台机器上就能同时跑 Windows 与 Linux，用于测试和开发。2001 年，VMware 推出 ESX Server 1.0，属于 Type 1，自带一套定制的内核，直接管理硬件并把物理机切给多台虚拟机，面向的是服务器整合。

ESX 的结构里保留了一个被称为服务控制台（service console）的 Linux 环境，用来运行管理代理、脚本与部分驱动，操作起来方便，代价是这块 Linux 本身也成了需要被信任、需要打补丁的庞大表面积。2007 年前后，VMware 推出 ESXi，把服务控制台整块去掉，管理职责改由远程接口与精简组件承担。这类把监控层做得尽量小、尽量少留可被攻击部件的思路，被称为薄 hypervisor（thin hypervisor）。ESXi 后来取代 ESX 成为主线，薄的程度成为衡量 hypervisor 质量的一个公开指标：能被信任的代码越少，隔离的边界就越清楚。术语上还需区分一层：「裸金属」（bare metal）在描述虚拟机监控器时指直接运行在硬件之上，在描述云服务时又指「给用户一整台没有 hypervisor 的物理机」，两个意思经常混用。

## 六、QEMU、Xen、KVM 与 Hyper-V：四条不同的路线

2000 年代，虚拟机监控器从单一厂商的产品扩散成多种技术路线，各自处理「谁来翻译指令、谁来代理设备」这两个问题的方式并不相同。

第一条路线是纯软件的全系统仿真。法布里斯·贝拉尔（Fabrice Bellard）于 2003 年发布 QEMU（Quick Emulator），用动态二进制翻译（dynamic binary translation）在一台机器上重现实另一套指令集的整机环境，既能做整机仿真（system emulation），也能做用户态仿真（user-mode emulation）。QEMU 自带大量外设模型，可以模拟一块网卡、一块磁盘控制器、一个显示适配器，让客户系统以为自己在真实硬件上启动。它起初与硬件虚拟化无关，靠翻译维持功能完整性，性能则受限。后来 QEMU 把处理器执行部分交给硬件加速器，自己专注于设备模型，成了 KVM 与 Xen 常用的设备前端。

第二条路线是半虚拟化（paravirtualization）。Xen 于 2003 年从剑桥大学计算机实验室的一组研究工作中成形，主要作者包括基尔·弗雷泽（Keir Fraser）与伊恩·普拉特（Ian Pratt）。它放弃了「假装硬件」的做法，要求客户系统经过修改，主动通过超调用（hypercall）与监控器协作，把敏感操作显式交给监控器处理。客户系统知道自己被虚拟化，因此放弃了需要繁琐模拟的部分，换来了当时难以达到的性能。Xen 于 2003 年在操作系统原理研讨会（Symposium on Operating Systems Principles，SOSP）上发表论文，随后走向商业化：XenSource 于 2005 年成立，2007 年被 Citrix 收购。

第三条路线是把监控器塞进操作系统内核。2006 年，阿维·基维蒂（Avi Kivity）在 Qumranet 公司启动内核虚拟机（Kernel-based Virtual Machine，KVM）。KVM 的做法不是再写一套独立内核，而是把 Linux 内核本身改造成监控器：一个内核模块提供 `/dev/kvm` 接口，虚拟机通过普通的 Linux 进程承载，由处理器的硬件虚拟化功能执行客户指令。KVM 于 2007 年并入 Linux 主线内核，Qumranet 于 2008 年被红帽（Red Hat）收购。KVM 在部署形态上接近 Type 1（直接使用硬件），在结构上却没有独立的监控器内核，边界与 Xen、ESXi 都不相同，这一区别在讨论「什么是 hypervisor」时经常被略过。

第四条路线来自操作系统厂商。微软早年通过收购 Connectix 取得 Virtual PC，又在 2005 年推出 Virtual Server。2008 年随 Windows Server 2008 发布的 Hyper-V 采用微内核化的结构：底层是一个极小的 hypervisor，管理操作系统（父分区）负责驱动与设备代理，客户分区通过它访问硬件。微软把这条路线与自家服务器操作系统捆绑销售，使 Hyper-V 成为企业侧的常见选项。

## 七、硬件接管：VT-x、AMD-V 与薄 hypervisor

二进制翻译虽然可行，代价始终存在：监控器要在运行时扫描并改写指令流，遇到自修改代码与复杂时序还要反复回退，开销难以压到很低。真正的转折点，是处理器厂商把虚拟化做进了芯片。

英特尔在 2005 年前后推出 VT-x（代号 Vanderpool，首批见于部分 Pentium 4 与 Xeon 型号，具体首发型号待核实），AMD 在 2006 年推出 AMD-V（代号 Pacifica）。硬件虚拟化引入了一个比内核态更高特权的运行模式，常被形象地称为「ring -1」，以及一组用于保存与恢复客户运行现场的数据结构（英特尔的虚拟机控制结构 VMCS，AMD 的虚拟机控制块 VMCB）。有了它，客户操作系统可以不加修改地运行在自己的最高特权级上，只有在执行少数真正敏感的操作时，处理器才自动陷入监控器。监控器不必再逐条翻译，二进制翻译的负担随之卸下。

内存一侧的硬件化同样改变了结构。早期监控器要为每台虚拟机维护影子页表，把客户页表逐项映射成真实页表，客户一改页表就要拦截重做。AMD 在 2007 年的 Barcelona 微架构上引入嵌套页表（Nested Page Tables，NPT），英特尔在 2008 年的 Nehalem 微架构上引入扩展页表（Extended Page Tables，EPT），让处理器用两级页表直接完成「客户虚拟地址到客户物理地址」再「客户物理地址到机器物理地址」的翻译。影子页表的拦截与重做被硬件一次走完，内存虚拟化的开销大幅下降。每一代处理器吃掉一项监控器原本要用软件解决的职责，监控器本身就能做得越薄：这既是 ESXi 去掉服务控制台的技术条件，也是后来「薄 hypervisor」成为卖点的原因。

## 八、I/O 与 DMA：设备如何被切开与透传

处理器与内存之外的第三块资源是输入输出（Input/Output，I/O）。设备虚拟化的最早动机来自一条实践观察：真正的瓶颈往往不在 CPU，而在设备。

设备与内存之间搬运数据，向来有两条路。一条是处理器亲自逐字搬运，占用运算时间；另一条是直接内存访问（Direct Memory Access，DMA），由设备控制器自己把数据从外设搬到内存或反向搬回，处理器只负责在搬完后收到一次中断。20 世纪 50 年代末，IBM 709 一类大型机引入数据通道（data channel），让外设与内存直接交换数据，处理器从「搬运工」变成了「指挥者」（该机制的首次出现年份待核实）。DMA 让 CPU 从与设备速率绑定的搬运中解脱出来，也埋下了后面几十年的一个方向：凡是可以不经过 CPU 的数据通路，都尽量从 CPU 手里拿走。

在虚拟化环境里，客户系统看到的设备未必是真实设备。监控器可以纯软件模拟一块网卡或磁盘控制器的寄存器与中断行为，客户系统的驱动照常工作，每一次寄存器读写都被陷阱拦截、由软件代劳。这种做法兼容性好，开销却高：每一次寄存器访问都要陷入监控器。2008 年前后，Rusty Russell 等人推动的 virtio 给出了一套折中方案：把常见的网卡、磁盘、控制台等设备抽象成一组标准化的、为虚拟化设计的前后端接口，客户系统使用专门的 virtio 驱动，直接与监控器里的后端交换数据环，不再逐个模拟寄存器。virtio 成为 KVM、QEMU 与 Xen 共用的设备模型，把「假装是真实硬件」改成「承认自己是虚拟设备」，这是半虚拟化思路在 I/O 上的延续。

设备透传是另一条路线。要让虚拟机直接用真实设备，需要解决一个安全问题：设备发起 DMA 时用的是物理地址，如果它被直接交给某台虚拟机，这块设备就可能读写到其他虚拟机的内存。输入输出内存管理单元（Input–Output Memory Management Unit，IOMMU）把地址翻译与访问保护扩展到设备一侧：设备发出的地址先经过 IOMMU 翻译并做权限检查，越界即被拦截。英特尔的对应实现叫 VT-d（Virtualization Technology for Directed I/O），随 2008 年的 Nehalem 落地；AMD 的对应实现叫 AMD-Vi。有了 IOMMU，设备可以被安全地分给某台虚拟机，中断也能被重映射到正确的客户。PCI-SIG 组织在 2007 年前后发布了单根 I/O 虚拟化（Single Root I/O Virtualization，SR-IOV）规范：一块物理功能（Physical Function，PF）可以派生出许多虚拟功能（Virtual Function，VF），每台虚拟机直接绑定一个 VF，网卡与虚拟机之间几乎不再经过软件交换。Linux 一侧则有 VFIO 框架负责把设备安全地交给用户态或虚拟机。

透传与 SR-IOV 换来了接近原生的速率，代价是把设备从监控器的视野里部分移走：监控器看不清这些数据包的走向，做流量统计、安全策略与在线迁移都变得麻烦。性能与可控性之间的这个取舍，正是后来把卸载逻辑搬回网卡（或让网卡本身变成一台可编程的机器）的直接起因。

## 九、存储状态：差分盘、快照与写时复制

比起 CPU、内存与设备，存储上被切开的是另一种东西——时间上的状态。一块磁盘可以被切成许多个「某一时刻的版本」，也可以被许多台虚拟机各自当成自己的盘。

支撑这件事的核心机制是写时复制（Copy-on-Write，CoW）。它的思想很朴素：有一份只读的基镜像，谁要修改某个数据块，系统不回头改基镜像，先把被改动的块写到另一处，再让指针指过去；没被改到的块继续与基镜像共享。于是同一份底层数据可以被许多份上层视图引用，新增的存储开销只与被真正改动过的数据量相关。写时复制在操作系统里最早被用于进程创建时的地址空间复制，虚拟化把它搬到了磁盘上。

具体实现散落在各家产品与技术里。微软 Virtual PC 与后来 Hyper-V 的虚拟硬盘（Virtual Hard Disk，VHD）提供差分盘（differencing disk）：在父盘之上挂一层子盘，子盘只记录改动，多台虚拟机可以共享同一父盘。VMware 的虚拟机磁盘（Virtual Machine Disk，VMDK）用快照与增量盘（delta disk）实现回滚与克隆。QEMU 的 qcow2（QEMU Copy-On-Write 格式第二版）把写时复制、快照与稀疏分配做进单一镜像文件。Linux 的逻辑卷管理（Logical Volume Manager，LVM）提供快照，允许对在线卷取一个时间点视图。存储系统一侧，NetApp 的 WAFL（Write Anywhere File Layout）文件系统以快照为基本能力，Sun 的 ZFS 于 2001 年由杰夫·邦威克（Jeff Bonwick）团队公布，把写时复制与校验和做成文件系统级特性，任一块被改写前都先写新块，旧版本得以保留。在资源分配层面，精简配置（thin provisioning）让一个逻辑卷对外声称的容量可以大于物理实际占用，空间按真正写入的块逐步兑现。

存储被切开之后，一台物理服务器上的许多虚拟机各自拥有一块随时可回滚、可克隆、可做备份时间点的盘。运维动作也随之改变：创建一台新虚拟机从安装整套系统改为从一份基镜像派生一层差分盘；回滚从恢复磁带改为丢弃增量层。磁盘从「一块设备」变成了「一棵以只读基镜像为根、以增量为枝的树」。

## 十、网络与 RDMA：把数据路径从 CPU 手里拿走

网络是 CPU 卸载这条线索上走得最远的一块资源。让处理器逐包处理数据，本质上是让它重复做算术上很轻、次数上极大的工作，效率低且挤占了真正需要算力的部分。要把这部分从 CPU 手里拿走，需要让网络接口卡（Network Interface Card，NIC）自己完成协议处理与数据搬运。

远程直接内存访问（Remote Direct Memory Access，RDMA）是这条路线上的标志性能力。传统网络收发里，数据要经过内核协议栈，接收方每收到一段数据都要产生一次中断、复制一次内存、再做一次上下文切换；RDMA 则让一台机器的网卡直接把数据写入另一台机器预先注册好的内存区域，绕过双方内核、不经中断、不额外复制，把一次远程内存操作做到接近本地访存的延迟。1997 年，Compaq、英特尔与微软联合推出虚拟接口架构（Virtual Interface Architecture，VIA）作为早期的标准尝试；1999 年，InfiniBand 行业协会成立，把两套竞争方案合并，随后发布 InfiniBand 规范并推动商业化，专做高速互联的 Mellanox 也在 1999 年成立（InfiniBand 规范的 1.0 版本发布年份待核实）。2010 年前后出现的 RoCE（RDMA over Converged Ethernet）把 RDMA 语义搬到以太网上，让数据中心在既有网络之上使用这套能力。NVIDIA 于 2019 年宣布、2020 年完成对 Mellanox 的收购，把这套互联技术纳入了自家数据中心布局。

值得留意的是这条线里一以贯之的动作：凡是 CPU 可以不必亲自做的数据搬运，就交给专门的硬件去做。DMA 把内存与外设之间的搬运交出去，RDMA 把跨机内存访问交出去，代价是硬件与软件接口变得需要约定（内存注册、队列对、完成通知），好处是数据路径上的处理器周期被整段省掉。虚拟交换机的卸载、SR-IOV 网络、以及后来的可编程网卡，都沿着这条线继续向前。

## 十一、SmartNIC 与 DPU：把基础设施本身变成一台机器

当网卡只负责搬运与卸载固定协议时，它仍然是一块外设。SmartNIC（智能网卡）与 DPU 把这条线推到了一个新的位置：网卡上开始集齐通用处理器、内存、总线接口与可编程加速单元，因而它本身就可以运行一套操作系统和一批软件。此时被切开的对象已经越过某一类具体资源，扩展到「运行基础设施这件事」本身。

SmartNIC 是较宽的叫法，指带有可编程能力、能把部分网络与存储处理卸载到卡上的网卡。DPU 是 NVIDIA 主推的更具体的叫法，指一块以网络为中心、自带多核 ARM 处理器、独立内存与 PCIe 通道，并集成网络、存储、安全加速引擎的片上系统，插在标准服务器里，作为一块独立的计算设备运行自己的操作系统与软件栈。它的定位可以概括为：把原本跑在服务器 CPU 上、用于支撑多租户与虚拟化的那些系统软件，整体挪到卡上。

围绕这一设想的产业动作集中在 2015 年以后。AWS 在 2017 年公布 Nitro 系统，用专用卡承担网络、存储与安全职责，把主机的虚拟化开销外移，这也是「裸金属云」得以对外提供接近无虚拟化开销实例的技术基础之一。NVIDIA 在收购 Mellanox 后推出 BlueField 系列，把 ConnectX 系列网卡与 ARM 处理器、可编程加速引擎组合成 DPU，后续几代持续提升带宽与卸载能力。Fungible 于 2015 年由普拉迪普·辛杜（Pradeep Sindhu）等人创办，专注数据处理器，2023 年被微软收购。Pensando Systems 于 2017 年由思科前高管团队创办，2022 年被 AMD 收购。英特尔在 2021 年提出基础设施处理单元（Infrastructure Processing Unit，IPU）这一叫法，同步给出基于专用芯片与基于现场可编程门阵列（Field-Programmable Gate Array，FPGA）的两条产品线。各家的名字不同，指向的机制一致：把网络、存储、安全与管理的职责从通用 CPU 搬到一块自带算力的专用设备上。

做到这一步，「一台机器」被拆开的层次就完整展开了。租户拿到的那台虚拟机，只包含它真正需要的处理器、内存与磁盘；支撑它存在的那套网络、存储后端、安全策略与调度逻辑，运行在另一台机器——那块 DPU——之上。DPU 拥有自己的操作系统、自己的管理界面、自己的升级路径，在监控器眼里它是一块设备，在自己的软件栈里它是一个完整的计算平台。从时间片到 DPU，被反复切开、分权、再缝合的对象，从 CPU 的一小段时间，扩展到一整套基础设施的运行职责。

## 十二、边界：当年的真实需求与后来的倒灌

在梳理这条线时，需要把不同年代的真实问题与后来才出现的概念分开放，否则容易把今天云、容器、零信任这些词汇倒灌回 1960 年代，把当年的工程动机说成对今日架构的预演。

当年真实存在的需求，按年代大致如下。20 世纪 60 年代，大型机采购与运行成本极高，一所机构往往只有一台机器却有许多部门与许多开发者，分时与 CP-67 要解决的是「怎样让许多人共用一台贵机器」以及「怎样在同一台机器上安全地并存多套系统的开发和测试环境」。20 世纪 90 年代末到 2000 年代，x86 服务器大量采买、单机利用率长期停留在很低水平，服务器散乱（server sprawl）与机房、电力、运维成本上升，VMware 一类方案要解决的是「把许多台低负载的物理机收进少数几台大机器」，以及开发、测试、容灾环境的快速复制。这一段的需求是整合与降本，不是多租户。

2006 年 Amazon 的 EC2 与 S3 上线，把虚拟化推向了按需租售；多租户隔离、在线迁移、镜像分发这些要求在这一阶段才成为硬约束，硬件的虚拟化扩展与内存虚拟化的硬件化大致与这一时期重叠，两者互为条件。2013 年 Docker 出现，把隔离挪到了操作系统层：它用 Linux 的命名空间（namespace）与控制组（cgroup）在同一内核里隔出许多互相看不见的文件系统视图与进程视图。容器与虚拟机解决的隔离层次不同，前者共享内核、后者各自带内核，把容器说成虚拟机的直接后代并不准确，两者更多是并置关系，云上常见的是「虚拟机里跑容器」的叠放。

零信任（zero trust）这一术语由 Forrester 的约翰·金德瓦格（John Kindervag）在 2010 年前后提出，「从不信任、始终验证」的表述属于 2010 年代的安全讨论，把它当成 CP-67 或 ESX 时代的设计目标并不成立。可观测性、无服务器（serverless）、服务网格（service mesh）、平台工程这些词汇的出现更晚。它们与虚拟化、DPU 共用了一批底层技术，却各有各的出发点。DPU 上确实会承载安全策略与微隔离（microsegmentation），但那是在已有虚拟化基础设施之上新增的职责，不是 1960 年代或 2000 年代的设计初衷。

## 十三、结论：拆层、分权、再缝合

把这条线连起来看，现代计算反复做的是同一类动作。面对一整台机器，找出其中可以被独立处理的一类资源，给它划出清晰的边界，配上专门的执行者，再通过一个稳定的接口把它重新接回整体。时间片把 CPU 的时间划给许多人，地址空间把内存划给许多进程，虚拟机监控器把整机划给许多操作系统与租户，virtio 与 SR-IOV 把设备划给许多虚拟机，差分盘与写时复制把磁盘状态划给许多时间点与许多机器，RDMA 与 DPU 把网络与基础设施职责划给一张自带算力的卡。

虚拟机在这条线上最显眼，原因在于它第一次把「一整台机器」当作可复制的单位，也因此直接改变了服务器采买、软件开发与运维的形态。但它既不是起点（前面的分时与虚拟内存已经把时间与地址切开了），也不是终点（后面的设备卸载与 DPU 正在把基础设施本身切开）。把它们串起来的，是同一组机制：翻译、截获、共享、写时复制、卸载，以及在这一切之上约定的接口。

2020 年以后，DPU 与 SmartNIC 的形态、标准与命名仍在变动，容器运行时、机密计算（confidential computing）、云原生网络这些方向也在继续改写边界。这一段按观察口径处理，不下定论；可以确定的是，把一台机器拆成很多台机器，再用接口把它们缝回去，这条线还没有走完。
